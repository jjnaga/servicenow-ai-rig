# Codex addendum — platform findings after the 2026-08-10 snapshot

> Scars learned 2026-08-11 on this instance (Australia patch 3). Read with `codex/servicenow.md`;
> these supplement it and win where they overlap.

- **An update set ships METADATA ONLY.** `--include-data` captures nothing — a full app publish
  produced identical row counts with and without the flag, even for declaratively seeded records. Any behavior
  that depends on a seeded row (a group whose membership drives approvals) needs a post-import
  setup lane **and a loud failure** (`gs.error` + a test asserting the data exists). For pure
  configuration work: make a **named update set current** (`sys_user_preference` name
  `sys_update_set`) *before* configuring, and count `sys_update_xml` rows after — data rows ride
  separately from config capture.
- **Take counts from `/api/now/stats/<table>?sysparm_count=true`, never `len(rows)` of a limited
  list read.** A capped list read of a table whose query clause silently dropped returns exactly
  the cap — a plausible number hiding the exact failure the bogus-field probe exists to catch.
- **A `STARTSWITH` filter on a name column silently over-counts by prefix overlap**
  (`u_x_supplier` also sweeps `u_x_supplier_contact`). Use `name=<t>^ORnameSTARTSWITH<t>.` and
  cross-check artifact counts against `sys_update_xml` after capture — the update set counts what
  you OWN, not what merely matches a string.
- **An unknown table name in any write lane fails SILENT-CLEAN.** Probe every non-obvious table
  name with a one-row GET first — the Table API answers `400 Invalid table` for a name that does
  not exist (e.g. the group-member M2M is `sys_user_grmember`, NOT `sys_user_group_has_member`).
- **(Fluent only) `StringColumn({choices})` creates `sys_choice` rows and leaves the field a
  free-text box** — use `ChoiceColumn({dropdown, choices})`. Should not matter on an OOB-config
  run (no custom schema), noted in case a test fixture tempts you.
